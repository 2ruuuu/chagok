# ticket-verify.md

티켓 인증 화면 · API · 테이블 만들 때 읽기
방향(왜 번거롭게 하는지)은 product.md 참고

## 원칙

- 위조를 완벽히 막는 건 불가능 (극장 예매 조회 공개 API 없음) -> 목표는 "위조 비용 > 카드 한 장 가치"
- 판정은 서버만: 클라이언트는 이미지만 보내고, 영화 · 극장 · 좌석 값은 서버가 뽑음
- tickets 테이블: 사용자는 select만, insert · update는 서버(admin-client, SECRET_KEY)만
  - 사용자가 콘솔에서 status = 'verified'로 insert하는 걸 막으려고
- user_id는 요청 body에서 받지 않고 서버에서 auth.getUser()로 꺼내기
- 리뷰 · 별점 · 메모 수정을 열 때도 status · 영화 · 좌석 컬럼은 못 바꾸게 (테이블 분리 또는 컬럼 단위 grant)
- LLM은 값 추출만, 진위 판단은 규칙 코드가 함 (이미지 속 "인증됨" 같은 문구에 안 속게)

## 자동 인증 vs 검수

- CGV · 롯데시네마 · 메가박스: 자동 인증
- 그 외 극장 (씨네Q · 독립 · 예술 · 작은영화관 등): 전부 검수 (pending)
- 3사여도 애매하면 pending: 인식 확신도 낮음, 필수 값 null, 영화 · 극장 대조 실패, 같은 시간 다른 극장
- 3사 티켓인데 영화를 못 찾으면 (KOBIS · TMDB에 없는 영화제 상영작 등) pending
- 관람일 제한 없음 (몇 년 전 티켓도 자동 인증 대상)
- 검수는 접수 후 24시간 안에 처리

## 지문 (중복 차단)

- 기본 지문: 체인 + 극장 + 상영일시 + 좌석 (정규화한 값) — 모든 티켓에 있고 짧아서 오독이 적음
- 보조 지문: 체인 + 예매번호 (있을 때만) — 긴 숫자라 오독 위험
- 둘 중 하나라도 겹치면 중복
- 기본 지문을 못 만들면 (극장 · 상영일시 · 좌석 중 null) pending
- 순서를 바꾼 이유 (샘플 5장 추출 테스트, 2026-11-15)
  - 예매번호가 없는 티켓이 있음 (롯데 종이)
  - 메가박스 종이 20자리 번호를 Haiku · Sonnet 둘 다 0 하나 빼고 19자리로 읽음
  - Sonnet이 멤버십 관람권 번호를 예매번호 칸에 넣음
- 정규화는 코드에서 (LLM에 맡기지 않음, 모델 · 실행마다 표기가 다름)
  - 상영일시: YYYY-MM-DD HH:mm (KST)
  - 좌석: "E열 10" · "E10" · "I-12" · "B - 4" · "D열 9번" · "B열1번" -> 열 문자 + 숫자 (E10, I12, B4, D9, B1)
    - 연속 좌석 한 줄 표기 "F열9-10번" · "F9~F10" -> F9, F10으로 펼침 (CGV 종이 티켓, 같은 열 · 최대 10자리, expandSeat)
  - 극장: "메가박스 코엑스" · "코엑스" -> 체인 이름 떼고 지점명만, 공백 제거
  - 예매번호: 숫자 · 영문만 남김 (하이픈 · 공백 제거)
- DB unique 제약, 동시 요청은 unique 제약이 막음 -> 23505 에러를 "이미 인증된 티켓" 화면으로
- 이미지 pHash도 저장 (같은 사진 잘라서 재업로드 차단, 출시 직후)
- 모바일 캡처 · 종이로 같은 예매를 두 번 인증하는 건 기본 지문(좌석 단위)이 막음
- 예매번호 위치: CGV 종이는 바코드 아래, 메가박스 종이는 [번호] + 바코드 아래, 롯데 종이는 없음, 모바일은 3사 다 있음

### 지문 잡는 시점

- 3사: 인식할 때 중복만 검사 -> 30분 임시 상태 -> 카드 발급 때 확정
- 검수 대상: [확인 요청하기] 누른 순간 잡음, 반려되면 풀어줌
- 같은 사용자의 임시 상태는 중복 검사에서 제외 (다시 올렸을 때 자기 자신 때문에 막히지 않게)
- 4번 화면에서 뒤로가기 · "새로 하기" -> 임시 상태 바로 해제
- 카드 삭제(휴지통) · 영구 삭제해도 지문 유지 -> 같은 티켓 재인증 불가 (인증 -> 삭제 -> 친구에게 넘기기 방지)

## 좌석

- 한 장에 좌석 여러 개(같이 예매)면 4번 화면에서 내 좌석을 고름
- 지문은 좌석 단위 -> 친구는 같은 캡처로 나머지 좌석 인증 가능
- 사진 한 장에 티켓 여러 장 -> 거절, "티켓 한 장만 나오게" (LLM이 ticket_count도 돌려줌)

## 라우트

- /verify (constants/nav.ts의 VERIFY_HREF, 하단 바 [인증] · TopNav가 이미 씀, 지금 페이지 없어서 404)
- 홈 "다른 티켓 인증하기" 버튼도 /verify로 연결 (지금 링크 없음)
- 하단 바 없는 화면 -> (main) 밖에
- 단계는 회원가입처럼 라우트로 나눔
  - /verify: 시작 · 인식 대기 · 실패 화면들
  - /verify/confirm -> /verify/rating -> /verify/review -> /verify/memo -> /verify/complete
- 진행 중인 인증 없이 중간 단계 URL로 바로 들어오면 /verify로 보냄

## 흐름

### 3사 (자동 인증)

1. 시작: 촬영 가이드 + [사진 찍기] [앨범에서 업로드]
2. OS 기본 카메라 또는 앨범
3. 인식 대기 (티켓을 읽고 있어요)
4. 관람 정보 확인
5. 별점 -> 관람 리뷰 -> 카드 메모
6. 발급 완료 -> [확인] -> /collection

### 검수 대상

1~4 같음, 4에서 검수 안내 + 버튼이 [확인 요청하기]
5. 확인 요청 완료 화면 -> [확인] -> /
6. 홈 "확인 중인 티켓"에 "확인 중"
7. 승인 -> "확인 완료" + 알림 -> 누르면 별점 -> 리뷰 -> 메모 -> 발급 완료
8. 반려 -> "확인 실패" + 알림 -> 누르면 /verify

- 별점 · 리뷰 · 메모는 승인 뒤에 씀 (반려돼도 버려지는 입력 없음)
- 승인 후 발급되는 카드도 VERIFIED (직접 확인했으니까)

## 화면별

### 1. 시작

- 예시 카드: 어제 박스오피스 상위 3편 포스터(TMDB, page.tsx)가 앞 · 왼쪽 뒤 · 오른쪽 뒤를 도는 입체 캐러셀 (_components/SampleCardCarousel.tsx, CSS 애니메이션만, 누를 수 없음). 못 불러오면 가상 포스터 verify-sample-1~3.webp. 포스터 저작권은 배급사에 있음 (정보 목적 사용, 수익이 생기면 다시 검토)
- 가이드: "티켓 전체가 나오게", "한 장씩"
- 사진 찍기: input type=file accept=image/* capture=environment
- 앨범에서 업로드: capture 없는 input
- 데스크톱: 업로드만 (사진 찍기 숨김)
- 커스텀 카메라 · 자동 촬영 · 갤러리 화면 없음 (OS 기본 카메라가 셔터 · 플래시 · 다시 찍기 다 해줌)
- 뒤로가기: 들어온 곳으로

### 업로드

- 클라이언트에서 리사이즈 · 압축 (긴 변 1600px 정도)
- 해상도가 낮으면 업로드 전에 다시 찍으라고 안내 (LLM 호출 전에 클라이언트에서 이미지 크기로 판단, 비용 안 듦)
  - 기준: 짧은 변 400px 미만만 막음 -> "사진이 너무 작아요" (원본으로 올려 달라는 안내, reason too_small)
    - 1000 -> 700 -> 400 (2026-11-22): 메신저로 받은 · 잘라낸 사진처럼 읽히는 진짜 티켓이 막혔음. AI 비용은 장당 약 $0.0007이라 아낄 이유가 약하고, 작은 사진 오독은 지점 · 영화 대조 · 확신도에서 걸려 검수로 감
  - 안내는 "티켓을 알아보지 못했어요" 화면 재사용
- 압축한 이미지를 인식 Route Handler로 바로 보냄 -> 서버가 ticket-images(private) 버킷에 저장 + 같은 바이트로 LLM 호출
  - signed upload URL 안 씀 (2026-11-22): 압축하면 보통 1MB 안쪽이라 Vercel 4.5MB 제한에 안 걸림, 왕복 · 경로 검증 · 고아 파일이 없어짐
  - 서버도 4MB 넘거나 이미지가 아니면 거절 (압축이 안 된 경우 대비)
- 원본 이미지는 검수 · 이의 제기 근거로 보관: 카드 발급 후 90일, 반려된 티켓은 30일 뒤 삭제 (지문은 계속 남김) -> 개인정보 처리방침에도 적기

### 3. 인식 대기

- [취소하기] · 뒤로가기: 요청 취소 (AbortController) + 임시 상태 해제 -> 시작 화면
- Route Handler maxDuration 확인 (LLM 몇 초 걸림)

### 4. 관람 정보 확인

- 영화: 포스터 (인증 전이라 VERIFIED 배지 없음), 제목, 제작연도 · 장르 · 러닝타임, 감독 · 출연 · 등급
  - 제작연도: KOBIS prdtYear (TMDB엔 개봉일만 있음)
  - 재개봉이면 재개봉 표시 (판정: 관람일이 최초 개봉일보다 1년 이상 뒤)
  - 장르 여러 개면 다 적고 넘치면 줄바꿈
  - 감독 · 출연(상위 3명): TMDB credits, 등급: KOBIS watchGradeNm
  - 줄거리는 뺌
- 관람 정보: 관람 일시 (날짜 + 요일 + 상영 시각, 예 2026.09.25 (목) 19:30), 극장 · 상영관 (특별관 이름 포함), 좌석 (여러 개면 칩으로 선택)
- 인식 결과 문구
  - 자동 인증: "티켓 정보를 인식했어요."
  - 검수 대상: "직접 확인 후 24시간 안에 카드를 발급해 드려요."
- 정보 수정 없음 (극장 · 관 · 일시 · 좌석은 보여주기만, 사용자가 고치면 결국 클라이언트 값을 믿는 셈)
- "정보가 다른가요?" -> 바텀시트 (components/bottom-sheet)
  - 다시 찍기
  - 확인 요청하기 -> pending, 원본 보고 값 고쳐서 승인
- "다른 영화예요" (후보 2~3개 중 선택): 나중에
- 뒤로가기: 확인창 없이 시작 화면, 임시 상태 해제

### 5. 별점

- 1~5 정수, "평점을 선택해 주세요."
- 나중에 수정 가능

### 6. 관람 리뷰

- 제목: "관람한 감상을 다른 관객들과 나눠보세요."
- 필수, 1자 이상이면 버튼 활성, 최대 500자 (넘으면 입력 막음)
- 사이트에 공개, 수정만 가능 · 삭제 불가
- 회원 탈퇴하면 자동 삭제, 카드를 휴지통에 넣거나 영구 삭제해도 리뷰는 남음
- 스포일러: has_spoiler 컬럼만 미리, UI 없음 (영화 상세에서 관람객 리뷰 전체를 흐리게 + "스포일러가 포함될 수 있어요" 버튼 예정)
- 신고: MVP에서 뺌
- 버튼: BottomCta + useKeyboardInset 재사용 (키보드 위로 올라감)
  - BottomCta는 AuthLayout 하단 여백 56px을 상수로 가짐 -> verify 레이아웃 여백 맞추거나 prop으로

### 7. 카드 메모

- 이름 "카드 메모"로 통일 (한 줄 메모 · 소감 · 나의 감상 같은 이름 안 씀)
- 제목: "카드 뒷면에 간직할 내용을 남겨보세요.", 소제목: "카드 메모 (선택)"
- 최대 500자 (넘으면 입력 막음), 카드 뒷면엔 3줄 넘으면 ...
- 버튼: 비어 있어도 "다음"
- 나중에 카드 상세에서 수정 (전체 내용은 "메모 자세히 보기" 모달)

### 8. 발급 완료

- 기존 TicketCard 사용 (카드 앞면엔 정보 없음), 시안 속 카드 모양은 안 씀
- 카드가 한 번 도는 홀로그램 연출 (product.md "카드 받는 순간 연출"), prefers-reduced-motion이면 생략
- 카드를 탭하면 뒷면을 볼 수 있음 (2026-11-22 변경, 처음엔 뒤집기 막기로 했었음). 카드 아래 "탭하면 뒷면으로" 안내는 카드 상세와 같음
- 뒤로가기 버튼 없음, 여기로 오는 이동은 router.replace
- 배경: 포스터 흐리게
- New 배지: 이 화면에만
- [확인] -> /collection
- [이미지로 저장] · [공유하기]: 공유 이미지와 같은 이미지 (카드 앞면 + 제목 · 개봉일 · 국가 · 장르 + 흐린 포스터 배경, 카드 상세 화면 구성)
- 공유하기: 바텀시트에 미리보기 -> OS 공유 창 (navigator.share files), 인스타 스토리 직접 공유는 웹에서 불가
  - 배경 색 고르는 옵션 없음
  - 이미지 공유 안 되는 브라우저(데스크톱 등)는 이미지로 저장만

### 확인 요청 완료 (검수 대상, 시안 없음)

- 제목 예: "티켓 확인을 요청했어요"
- 내용 예: "직접 확인 후 24시간 안에 알려 드릴게요. 확인이 끝나면 별점과 리뷰를 남기고 카드를 받을 수 있어요."
- [확인] -> /

### 예외 화면

- 이미 인증된 티켓: [문의하기] -> /settings/contact, 티켓 이미지 자동 첨부 (이의 제기 경로)
- 자동 인증이 어려운 티켓 (3사 외 · 거의 못 읽음): 버튼은 [확인 요청하기] (시안의 [문의하기]에서 변경), 영화 정보 확인 없이 사진만 접수
  - 3사 외인데 인식이 됐으면 이 화면 대신 4번 화면 (검수 안내 + [확인 요청하기])
  - 거의 못 읽었을 때만 이 화면
- 알아보지 못한 이유별 안내 (2026-11-22, RecognizeResult unreadable.reason)
  - not_ticket(AI가 티켓 아님으로 판단): "티켓 화면이 아니에요" + 모바일 티켓 · 종이 티켓을 올려 달라는 안내, 팁 없음
  - multiple(티켓 여러 장): "티켓이 여러 장 보여요", 팁 없음
  - future(상영 전): "아직 상영 전인 티켓이에요" + [확인]만 (다시 찍어도 같아서)
  - 이유 없음(해상도 부족 · 이미지 못 읽음): 아래 기본 안내
  - 목: ?mock=not_ticket · multiple · future
- 티켓을 알아보지 못함: 팁 5개 (전체가 화면 안에 / 빛 반사 없이 밝은 곳에서 / 구겨진 종이 티켓은 펴서 / 제목 · 일시 · 극장 · 좌석이 보이게 / 티켓은 한 장만)

## 홈 "확인 중인 티켓" 섹션

- 검수 대상 티켓이 없으면 섹션 숨김
- 순서: 확인 완료 -> 확인 중 -> 확인 실패, 3개 + 더보기
- 확인 중: 날짜 · 극장 표시, 누르면 토스트 "직접 확인 중이에요. 24시간 안에 알려 드릴게요"
- 확인 완료: "별점과 리뷰를 남기고 카드를 받아보세요", 누르면 별점부터
  - 기한 없이 남음, 다 쓰고 카드 받으면 섹션에서 빠짐
- 확인 실패: 사유 표시 (사진이 흐려요 / 티켓이 아니에요 / 이미 인증된 티켓이에요), 누르면 /verify
  - 다시 인증하거나 7일 지나면 사라짐
  - 반려되면 지문 풀어줌 -> 같은 티켓으로 다시 시도 가능
- 태블릿 · 데스크톱: 나중에 반응형 한 번에
